## 5. Discrimination evidence for the claim-eviction tests

test_307/test_308 were themselves defective at first: they passed against the buggy design, so
they proved nothing. Two harness defects were found and corrected, recorded here rather than
quietly fixed:

  a) The victim's counter was driven to zero before the replay. An emptied counter is deleted
     (identically on Redis), so the replay was refused by "no counter", not by the claim. Fixed
     by keeping the victim's counter non-empty.
  b) The earlier pressure loop counted *refused* admissions (token is None past the threshold)
     as claims, so it applied almost no pressure while the bound was still 10,000. Fixed by only
     counting real admissions and by asserting eviction was actually observed.

With the assertions corrected, the same tests were run against the original store to prove they
discriminate. Against the buggy design:

    test_307 -> FAILED  "a live claim was forgotten under pressure from other accounts,
                         so the same token was refunded twice (count 2 -> 1)"
    test_308 -> FAILED  "harness: the old global set still holds the claim, so eviction was
                         not exercised"

Against the fixed design both pass. That comparison is the evidence; a test that passes both
ways would prove nothing.
